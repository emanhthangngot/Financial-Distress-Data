## Architecture

`scripts/_phase2_rubric_items.py:1159` holds `EXECUTED_RUBRIC_IDS`; membership
there is what flips a row from `design_only` to executed
(`_phase2_rubric_items.py:1225`). Adding the two IDs without their evidence
files present makes the auditor fail on a missing artifact — the correct
failure, and the reason the registration step comes after phase 3, not before.

The gate that matters is the same one `260811-1627` runs, minus the cuts:

```bash
PATH="$PWD/.venv-phase2/bin:$PATH" .venv-phase2/bin/python scripts/audit_phase2_evidence.py \
  --strict --require-executed --run-validations --track LLM --ml 100 --llm 100 \
  --phase1-base ddbcbe7bd41ae4883954b8a247efdc67c7329078 \
  --gitops-root ~/Studying/FSDS/financial-distress-gitops
```

No `--accept-design-only`. `PATH` is prefixed so the ~60 `validation_command`
subprocesses resolve `pytest` from `.venv-phase2`. `--phase1-base` is
`ddbcbe7b…` — the only value that passes the protected-path diff, and it is
recorded nowhere else, so it must be carried forward verbatim.

This plan does **not** stamp SHAs. Stamping is `260811-1627` phase 6's job, and
its ordering rule is strict: every document and report committed **before** the
stamp, because `_only_evidence_sha_lines_changed`
(`scripts/audit_phase2_evidence.py:609-638`) invalidates all evidence for any
post-stamp commit touching anything but `source_sha`/`gitops_sha` lines. The
last thing this phase does is confirm nothing is left to write.

## Risk Assessment

- **Dirty worktree fails the gate for a reason unrelated to evidence.** The
  known trap: an untracked plan directory alone trips
  `source checkout is not clean`. Mitigation: step 5 is explicit and precedes
  the gate.
- **A `validation_command` subprocess fails because `PATH` was not prefixed.**
  Mitigation: the command above is copied verbatim, prefix included.
- **`--phase1-base` value lost.** It exists in no tracked file. Mitigation: it
  is written into this phase and into `260811-1627`'s plan; carry it verbatim.
- **Registering the rows before the evidence lands.** Produces a confusing
  auditor failure. Mitigation: dependency on phase 3 is hard; do not
  pre-register to "save a step".
- **Post-stamp commits invalidate the evidence.** Not this phase's action, but
  its last step exists to guarantee nothing is left to write when phase 6 starts
  stamping.
