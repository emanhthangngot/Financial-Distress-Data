# Phase 2 evidence captures

Evidence is split into two layers:

* Canonical rubric evidence files are the row-level claims under `llm/` and
  `ml/`. They are stamped with the evidence contract and must not be rewritten
  by a capture run.
* Repeatable capture output lives under `captures/<run-id>/`. Each run contains
  command logs and a `manifest.json` generated by
  `scripts/capture_phase2_evidence.py`.

Reference semantics are explicit: a relative source link points to the current
checkout; a URL pinned to a full commit SHA is historical proof; and a log,
screenshot, metric, or timestamp describes the captured run rather than the
current live state. The checklist in `configs/evidence-checklist.yaml` is the
authoritative list of commands and claims.

The capture driver is intentionally fail-closed. If any declared command fails,
the run manifest is marked `fail` and the process exits non-zero. A section that
declares a screenshot also fails unless its screenshot command succeeds and
produces at least one file; this prevents a successful command log from being
mistaken for visual evidence. When `--source-sha` or `--gitops-sha` are omitted,
the driver records the checkout `HEAD` values (or an explicit `unresolved`
marker when a checkout cannot be inspected) in the run manifest.
